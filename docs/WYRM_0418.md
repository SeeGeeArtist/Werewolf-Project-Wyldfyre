# 0.4.18 - Wyrm Infection, Garou Guide, wolf mesh and tail

## Lore and rules

The Knox virus is a bioweapon engineered by Wyrm-corrupted humans. To a
Garou it is the **Wyrm Infection**, and only the war form purges it fast.

| | Berzerker (Crinos) | Near-Human / Near-Wolf | Human / Wolf |
|---|---|---|---|
| Wyrm Infection purged in | 5 min (300 s) | 15 min (900 s) | never |
| Zombie bite closes after | 5 min | 15 min | vanilla |
| Other wounds close after | 60 s | 180 s | vanilla |
| Body-part health | 2.0 /s | 0.7 /s | vanilla |

Constants: `WTAGarou.WyrmInfection.PURGE_SECONDS`,
`WTAGarou.Regeneration.CLEAR_BITES_AFTER`, `INFECTION_PER_SECOND`
(`shared/WTAGarouDefinitions.lua`). The purge counter is `d.infectionBurn`
(0..100) as in 0.4.17; the cure still goes through
`WTAGarou.ClearZombieInfection` once it reaches 100 (with float slack).

A bitten body part keeps *all* of its wound flags until its bite clock runs
out, because `clearWound` clears a part in one go. Health and bleeding on
that part still regenerate at the form's rate, so the bite is cosmetic and a
reminder, not a bleed-out risk.

## Health panel line

`client/WTAGarouHealthPanel.lua` post-hooks `ISHealthPanel.render`. After
the vanilla render, if the character is a Garou with the infection, it draws
`- Wyrm Infection (purging 40%, 3:00 left in Berzerker)` (green while a
purging form is held, violet otherwise:
`(40% purged; shift to Berzerker to continue)` / `(only Berzerker purges
it)`) at the top of the body-part list and pushes the list down one line.
The server sends `wyrm = d.infectionBurn` in every `RageSync`. Vanilla shows
the zombie infection only in cheat mode, so this is the player's only
in-game read-out. Errors in the hook are pcall-guarded and logged once.

## Berzerker tooltip

`Reduces wyrm infection.` (green) is inserted above the Rage-burn line.

## Garou Guide (tutorial infrastructure)

`client/WTAGarouTutorial.lua`:

* `WTAGarou.Tutorial.buildPages()` returns the ordered pages
  (`{ title, body }`, ISRichTextPanel markup, no `<SIZE>`/`<H1>`). The five
  draft pages cover: You are Garou, Five forms, Rage, Clothes/Strip/Dress,
  Wounds/silver/Wyrm. They read display names and constants at build time.
* `WTAGarouTutorial` window (ISCollapsableWindow 460x340): rich-text body,
  `< Back` / `Next >` / `Close`, title `Garou Guide  n/N  -  <title>`, and
  an `ISTickBox` **Don't show again**.
* Persistence: player mod data `WTAGarou_TutorialSeen` and the per-install
  file `Zomboid/Lua/WTAGarou_tutorial.txt` (`seen=1`), so a new character
  does not re-trigger it; unticking re-enables it.
* Auto-open one tick after `OnCreatePlayer` for an unseen Garou;
  `WTAGarou.Tutorial.open()` from the Garou panel's new **Guide** button
  (right column, row 3).

## Wolf head/neck deformation - root cause and fix

Static analysis of the B42.20.2 engine and the GLBs ruled out layered human
clips, missing keyframes, scale keys, inverse-bind-matrix mismatches and
influence counts. The cause is the body mesh itself: WolfMod's
`Wolf.glb` (1687 vertices) weights every head-dominant vertex only ~0.29 to
`Bip01_Head` and spreads the rest over `Bip01_Neck` and `Bip01_Spine1`, so
the head is dragged toward the spine whenever the neck bends (eat: 8.5 cm
mean / 29 cm max deviation from rigid head motion in an engine-style CPU
skinning simulation; walk bob: 5.5 cm). The mesh embedded in the animation
GLBs (3433 vertices, same bounds and texture layout, what a GLB viewer
shows) is weighted properly (0.7-0.83 dominant, < 1 cm).

`tools/build_wolf_body.py` now builds `common/media/models_X/Skinned/
WTAGarou_Wolf.glb` from `Wolf_walk.glb` (drops the animation, prunes unused
buffers, keeps `Dummy01 -> WTAGarou_RigRoot -> Bip01 ... / Wolf /
Translation_Data`). The model scripts, loader and Java rig checks are
untouched: the same file still serves as `meshFile` and `animationsMesh`.
`tests/asset_contract_test.py` asserts the weights so the WolfMod body can
never come back silently. The previous file is in git history
(`git show 45438ce:WTAGarou/common/media/models_X/Skinned/WTAGarou_Wolf.glb`).

## Tail

`tools/lift_wolf_tail.py` rewrites the `Bip01_Tail` rotation keys (angle
about each key's own axis, in place): walk 169.6 -> 125 deg (down and back),
run / run_V3 / run_fourx 169.6 -> 105 deg (about 40 deg below level).
`Wolf_idle` (149.4, straight down) and `Wolf_run_V2` (83.5, level) are left
alone. Rerun with `python3 tools/lift_wolf_tail.py Wolf_walk=130 ...` to
tune.

## Shift sound cues

Author-supplied one-shots in `common/media/sound`, bank entries in
`scripts/wtagarou_sounds.txt` (all `loop = false`):

| Trigger | Sound | File |
|---|---|---|
| any shift channel starts | `WTAGarou_FormShift` | WTAGarou_formshift.ogg |
| the Crinos shift lands (channelled or Rage-forced) | `WTAGarou_CrinosShift` | WTAGarou_Crinos_Shift.ogg |
| forced-Crinos countdown starts | `WTAGarou_CrinosShiftTimer` | WTAGarou_Crinos_Shift-Timer.ogg |

`client/WTAGarouShiftSounds.lua` plays each cue once per trigger: the
channel action plays on `start()` only (guarded), the completion cue is
de-duplicated per player within one second, and the previous handle of the
same cue is stopped before a new one starts, so quick re-triggers replace
rather than stack. The countdown used the Crinos growl before; the growl is
still the crouched Crinos shout.

## Is the purge cumulative?

Yes, and since the second 0.4.18 patch so is wound closing. `d.infectionBurn`
(0..100) and `d.woundProgress[part]` (0..1) live in the Garou's mod data and
are only reset when the infection is cured / the wound is gone. Each second
in a form adds `1/window` for that form, so 2 min Berzerker (40%) followed by
9 min Near-Human or Near-Wolf (60%) cures a bite and the virus; Human/Wolf
add nothing but lose nothing. Before this patch the wound clock was a
first-seen timestamp that reset on every form change.
