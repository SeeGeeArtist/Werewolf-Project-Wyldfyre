# 0.4.15 - clothing profiles, moon-phase icons, display names

Requested after the 0.4.13/0.4.14 build, before its playtest. Nothing here
was verified in game; the Lua suite and the asset contract cover the logic
and the files.

## Clothing on shift (WTAGarou.ShiftStrip.FORMS)

Damage is a whole number of condition points derived from a common T-shirt,
not a share of the item's own maximum. Clothing scripts in B42.20.2 do not
set `ConditionMax`, so the engine default applies: `conditionMax = 10` in
`zombie/scripting/objects/Item.java` (and `InventoryItem.java`); the T-shirt
pages on pzwiki.net list no ConditionMax either
(https://pzwiki.net/wiki/T-shirt). 10% of a T-shirt = 1 point. Vanilla ties
condition to holes (`Clothing.getCondLossPerHole = max(1, ConditionMax /
coveredParts)`), so a jacket with a higher ConditionMax loses more per hit in
vanilla but the same points from a shift here, as requested.

| Form | Points | Holes | Drops | Note |
| --- | --- | --- | --- | --- |
| Homid | 0 | 0 | no | untouched |
| Glabro (Near-Human) | 1 (10%) | 0 | **no** | seams strain, nothing comes off, no model reset |
| Lupus (Wolf) | 1 (10%) | 1 | yes | slips out |
| Hispo (Near-Wolf) | 3 (25% -> 2.5, rounded up) | 2 | yes | the 0.4.11-0.4.14 amount for a T-shirt |
| Crinos (Berzerker) | 4 (1.5 x 2.5 = 3.75, rounded) | 3 | yes | explosive |

- Headwear and masks (`NO_DAMAGE_LOCATIONS`: Hat, FullHat, SweaterHat,
  Bandana, Mask, MaskEyes, MaskFull, Headband) are never damaged, but still
  drop for the dropping forms. Some hats double as masks; one rule for both.
- Unchanged: `SAFE_LOCATIONS` (jewelry, glasses, belts, holsters, webbing,
  bag slots, saddlebag), worn containers, held items and carried items are
  never touched; condition floors at 1; the Strip action still queues
  vanilla unequips and damages nothing.
- `WTAGarou.Clothing.dropForbidden` returns the DROP count (Glabro returns
  0); the test panel line says "strained N" for Glabro.

## Tooltip size fix

`ISToolTip` lays the description out with `ISRichTextPanel` and then measures
every line with the tooltip's DEFAULT font (`ISToolTip.lua`, layout loop over
`self.descriptionPanel.lines` with `MeasureStringX(defaultFont, v)`). Any
`<SIZE:...>` or `<H1>` face larger than the default therefore draws wider
than the box: the Crinos Rage line overflowed. All form tooltips now use
the default size only; emphasis is colour.

## Display names and tooltips

`FormData.<form>.displayName` and `WTAGarou.DisplayName(form)`:
Homid = Human, Glabro = Near-Human, Crinos = Berzerker, Hispo = Near-Wolf,
Lupus = Wolf. Used by the panel buttons, the current-form line, the
countdown/channel lines, the keyboard radial and the controller radial.
The lore name stays the key everywhere in code, net messages and mod data.
Tooltips open with the lore name in a warm highlight, then the description,
then the Rage line. Vanilla rich text has no bold tag (`RichTextLayout.lua`
handles LINE, BR, H1/H2, TEXT, CENTRE/LEFT/RIGHT, RGB, GHC/BHC, RED/ORANGE/
GREEN, SIZE, IMAGE, INDENT, JOYPAD, SETX), so "bold" is the highlight colour
at the same size.

## Icons (media/ui/WTAGarou, 48x48 RGBA, non-interlaced)

Generated by `tools/gen_radial_icons.py` (Pillow + numpy, 8x supersampled).

| File | Phase | Colour |
| --- | --- | --- |
| wta_homid.png | new moon: ring | white |
| wta_glabro.png | waxing crescent | amber |
| wta_crinos.png | half moon | blood red |
| wta_hispo.png | waxing gibbous | amber |
| wta_lupus.png | full moon | white |
| wta_strip.png | T-shirt with a red slash | grey / red |

Each moon carries a paw-print crater (pad + four toes) in a darker shade of
its own colour on the lit face; the new-moon ring carries a faint one on its
dark disc. The unlit face is a faint dark disc so the phase reads as a moon.
The previous fox-head icons are replaced. The strip icon did not exist
before (the slice drew without a texture).
